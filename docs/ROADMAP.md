# 개발 로드맵

웹(브라우저 단독) 기준 계획이다. 각 단계 끝에서 태그를 붙여 Git 로그에 단계 경계를 남긴다.

## 기본 구조

**백엔드가 없다.** OCR 추론, 이미지 전처리, 데이터 저장, 통계 집계가 모두 브라우저 안에서
일어난다. 서버는 정적 파일(HTML/JS/모델)을 내려주는 역할만 한다.

```
브라우저
 ├─ 입력      카메라 / 파일 선택
 ├─ 전처리    OpenCV.js
 ├─ 추론      ONNX Runtime Web + PP-OCRv5 모델
 ├─ 파싱      자체 구현 (좌표 라인 그룹핑 → 금액 분리 → 교차검증)
 ├─ 저장      IndexedDB
 └─ 집계      여행별 / 카테고리별 통계

정적 서버 (nginx)  ← HTML, JS, OCR 모델(.tar) 만 제공. 데이터는 받지 않는다.
```

이 구성은 교수님이 조언하신 "백엔드 없이 내부 저장으로 간소화"를 그대로 만족하면서
제안서의 웹 서비스 형태도 유지한다.

## 단계별 계획

| 단계 | 내용 | 완료 기준 | 태그 |
|---|---|---|---|
| **P0** | 저장소 뼈대, 도커 개발환경, 브라우저 환경 검증 | 팀원 3명 모두 `make dev` 로 환경 점검 화면 확인, 필수 항목 전부 통과 | `v0.1-env` |
| **P1** | 화면 구조 (더미 데이터) | 홈 / 스캔 / 영수증 상세 / 통계 / 설정 화면 전환 동작 | `v0.2-ui` |
| **P2** | IndexedDB 스키마와 CRUD | 여행·영수증·품목 저장/조회/수정/삭제, 새로고침 후에도 유지, 영구 저장 권한 요청 | `v0.3-db` |
| **P3** | 이미지 입력과 전처리 | 카메라 촬영 / 파일 선택 → OpenCV.js 전처리(그레이스케일·기울기 보정·이진화) 결과 미리보기 | `v0.4-capture` |
| **P4** | OCR 엔진 연동 | 오프라인 상태에서 한국어 영수증 텍스트 인식 성공, 처리 시간 측정 | `v0.5-ocr` |
| **P5** | 영수증 파서와 검수 UI | 날짜·상호·품목·금액 추출, 품목합계와 총액 교차검증, 사용자 수정 화면 | `v0.6-parser` |
| **P6** | 지출 관리 기능 | 여행별·카테고리별 집계, 통계 화면, CSV 내보내기, 다국어 모델 전환 | `v0.7-expense` |
| **P7** | 테스트와 CI | 파서 단위 테스트, 인식 정확도 측정표, GitHub Actions 빌드·테스트 통과 | `v0.8-test` |
| **P8** | 시연 준비와 문서 | 설치 가이드, 아키텍처 문서, 발표자료, 최종보고서 | `v1.0` |

## 제안서 대비 변경점

| 항목 | 제안서 | 현재 | 사유 |
|---|---|---|---|
| 실행 형태 | Flask 웹 서비스 | 브라우저 단독 웹 앱 | 백엔드 축소 (교수님 조언) |
| 서버 | Flask (Python) | 정적 서버만 (nginx) | 데이터를 서버에 보내지 않음 |
| 데이터 저장 | 서버측 SQLite | 브라우저 IndexedDB | 동일하게 관계형 구조 유지, 위치만 단말로 |
| OCR 실행 위치 | 서버 (Python PaddleOCR) | 브라우저 (ONNX Runtime Web) | 백엔드 제거에 따른 변경 |
| OCR 엔진 | PaddleOCR | PaddleOCR (유지) | 제안서 기술 스택 유지 |
| 전처리 | OpenCV | OpenCV.js (유지) | 같은 라이브러리의 WASM 빌드 |
| 파싱 로직 | 자체 구현 (Python) | 자체 구현 (TypeScript) | 알고리즘 동일, 언어만 변경 |

**핵심**: 제안서의 기술적 기여(OpenCV 전처리 + 좌표 기반 파싱 + 품목합계 교차검증)는
그대로 유지된다. 바뀐 것은 실행 위치(서버 → 브라우저)뿐이며, 오히려 다음 장점이 생겼다.

- 영수증 사진이 네트워크로 나가지 않는다 (제안서가 내세운 개인정보 측면의 강점이 강화됨)
- 오프라인에서 동작한다 (해외여행 중 데이터 로밍 없이 사용 가능 — 주제와 잘 맞음)
- 서버 운영·배포 부담이 없어 시연이 단순하다

보고서에서는 이 점을 "백엔드 제거라는 제약을 설계 개선으로 전환"으로 서술하면 된다.

## 단계별 리스크

| 단계 | 리스크 | 대응 |
|---|---|---|
| P3 | 브라우저별 카메라 동작 차이 (특히 iOS Safari) | 파일 선택 입력을 항상 함께 제공. 시연은 Chrome 기준 |
| P4 | WASM 추론 속도가 느림 | COOP/COEP 로 멀티스레드 활성화(P0 에서 확인 완료), 입력 긴 변 960px 축소, WebGPU 백엔드 검토 |
| P4 | 첫 진입 시 모델 17.4MB 다운로드 | 캐시 헤더로 재방문 시 재다운로드 방지. 시연 전 미리 1회 로드 |
| P5 | 영수증 양식 편차로 파싱 실패 | 교차검증 실패 건은 검수 화면으로 보냄. 100% 자동화를 목표하지 않음 |
| P6 | 외화 환율 (여행 영수증 특성) | 내장 환율표 + 수동 입력이 기본. 외부 환율 API 는 선택 기능 |
| 전반 | 브라우저 데이터 삭제 시 기록 소실 | P2 에서 영구 저장 권한 요청 + P6 의 CSV 내보내기로 백업 경로 제공 |
