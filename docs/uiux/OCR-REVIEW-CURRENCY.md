## 문제와 동작

사진 등록의 ‘저장하고 내용 입력’은 사진·OCR 원문과 빈 영수증을 먼저 저장한다. 기존에는 수정 폼에서 추출된 내용을 저장하기 전에 이탈한 다음, 빈 상세에서 ‘확인 완료로 표시’를 누르면 자동 채우기 조건이 꺼졌다. 원문은 남아 있어도 입력 칸은 빈 상태가 됐다.

- OCR 원문이 있는 수정 화면에 ‘OCR 결과 반영’을 제공한다. 인식 엔진을 다시 돌리지 않고 기존 원문과 파서를 사용한다.
- OCR로 추출 가능한 현재 값이 추출 결과와 같으면 비활성화한다. 다르면 상태가 확인됨이어도 활성화한다.
- 반영할 항목에 현재 입력이 있으면 덮어쓰기 확인창을 띄운다. 취소하면 입력을 유지한다. 빈 상태는 바로 반영한다.
- 상호·결제 일시·품목·총액 중 추출된 항목만 바꾼다. 추출하지 못한 필드·선택 통화·부가세 입력·환율은 유지한다. 품목은 추출 목록이 있을 때 목록 전체를 교체한다.
- ‘저장’을 눌러야 DB에 반영한다. 추출 가능한 항목이 아예 없으면 기존 값을 지우지 않고 직접 입력을 안내한다.
- 배스킨라빈스의 별도 추출 문제는 이 변경으로 원인이 밝혀지거나 수정된 것으로 간주하지 않는다.

확인됨은 현재 내용에 대한 사용자 판단이다. 상호·결제 일시·통화·총액·부가세·품목·분류·사진 연결·소속 여행이 실제 변경돼 저장되면 확인 상태를 해제하고 다시 교차검증한다. 내용이 같거나 취소하면 확인 상태를 유지한다. 저장용 품목 ID가 다시 만들어지는 것은 내용 변경으로 세지 않는다. 환율 메타데이터 보완만으로는 OCR 검수 상태를 바꾸지 않는다.

빈 품목과 총액 0은 내용 대기로 판정하고, 0=0을 교차검증 통과로 표시하지 않는다. 상세와 저장소 양쪽에서 빈 내용의 확인 완료 처리를 막는다. 기존 빈 확인됨 기록은 수정 화면의 OCR 버튼으로 복구할 수 있다.

## 통화와 환율

- 여행의 ‘집계 기준 통화’와 영수증의 ‘결제 통화’를 구분한다. 영수증 원금액·통화는 유지한다.
- 같은 통화는 그대로 집계한다. 다른 통화는 결제일 기준 Frankfurter 참고환율을 자동 조회한다. 직접 입력도 가능하다.
- 결제일은 현재 앱 날짜 표시와 같은 브라우저 로컬 달력 날짜다. 입력한 날짜의 통화쌍 환율을 요청하며, 응답의 실제 제공일도 함께 저장·표시한다. 휴일 등은 서비스가 반환하는 이전 최근 제공일을 사용한다. 미래일·조회 실패·유효하지 않은 응답은 환산 대기로 둔다.
- 환율·조회 기준일·실제 제공일·출처·기록 시각을 영수증에 선택 필드로 저장한다. 이미 저장된 값은 다시 열 때 갱신하지 않는다. 통화쌍·결제일별 로컬 캐시를 사용하며 동시 중복 요청을 공유한다.
- 날짜나 결제 통화가 달라지면 맞지 않는 이전 환율은 적용하지 않는다. 여행 기준 통화가 바뀌면 새 통화로 조회하고 이전 기준 통화의 기록도 보존한다.
- 환율이 없더라도 영수증 저장을 막지 않는다. 합계는 ‘집계 가능액’과 ‘환산 대기 N장’으로 표시한다. 원숫자를 그대로 더하거나 전체 총액인 것처럼 표시하지 않는다.
- 여행 목록·여행 상세·통계·월별 추이·여행 비교·CSV가 공통 환산 함수를 사용한다. 전체 추이와 여행 비교는 여행의 기준 통화가 같은 경우끼리 묶는다.
- 총지출은 기존처럼 검수 전 영수증 총액도 포함한다. 품목 분류·월별 추이·여행 비교는 검수가 끝난 영수증만 집계한다. 환산 대기와 내용 대기는 해당 집계에서 제외하고 누락을 알린다.
- 환산은 통화별 최소 단위로 반올림한다. 총액은 영수증별, 품목은 품목별로 반올림하므로 합계에 작은 반올림 차이가 있을 수 있다. 환산 곱셈·합산은 정수 비율 연산을 사용한다. 원·엔·동은 정수, 달러 등은 소수 둘째 자리다. 교차검증 허용 오차도 해당 통화의 최소 단위 1개로 맞춘다.
- CSV는 원 통화·품목금액·영수증 총액·부가세와 기준 통화·적용 환율·기준일·출처·환산 상태·환산액을 구분한다. 영수증 총액과 부가세는 첫 품목 행에만 기록해 중복 합계를 피한다. 환산 대기의 환산값은 빈칸이다.
- DB 버전과 기존 스토어는 유지한다. 선택 필드를 읽지 않는 구버전에서도 원본 영수증을 읽을 수 있다. 사진·상호·금액은 환율 서비스에 전송하지 않으며 통화 코드와 기준일만 조회한다.

## 사용자 검수 순서

1. OCR 원문이 남은 빈 영수증 수정 화면에서 ‘OCR 결과 반영’ → 저장. 품목·총액 복구와 버튼 상태를 확인한다.
2. 입력값을 고친 뒤 OCR 버튼의 확인창을 취소·승인한다. 저장 전에는 상세 데이터가 바뀌지 않는지 확인한다.
3. 확인됨 영수증을 변경 없이 저장하면 유지되고, 금액을 바꿔 저장하면 일치 여부에 따라 인식 완료·검수 필요로 바뀌는지 확인한다.
4. 테스트용 여행을 KRW, 영수증을 USD로 두고 원금액 10·품목 합계 10·직접 환율 1400을 입력한다. 상세 원금액 USD 10과 환산액 KRW 14,000, 여행 합계·통계·CSV가 맞는지 확인한다. 다시 열어 환율 고정을 확인한다.
5. 자동 조회와 결제일 변경을 확인한다. 여행 기준 통화를 JPY로 바꿔도 영수증 원통화·금액이 그대로인지 확인한다.
6. 네트워크가 끊긴 새 통화·날짜에서 저장한 기록은 환산 대기로 표시되는지, 직접 환율을 입력하면 집계가 복구되는지 확인한다.
7. 좁은 화면에서 OCR 버튼·환율 입력·안내문 배치를 확인한다.
