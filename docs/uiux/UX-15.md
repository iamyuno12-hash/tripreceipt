- 작성일: 2026-11-23 (한국 시간)

## 확인한 집계 기준

| 화면·금액 | 포함하는 상태 | 사용하는 금액·범위 |
| --- | --- | --- |
| 여행 목록·여행 상세의 총지출 | 인식 완료·확인됨·검수 필요 | 저장된 영수증 총액. 여행의 기준 통화로 환산 |
| 월별 지출 추이 | 인식 완료·확인됨 | 결제일 기준 1년 전 같은 달부터 이번 달까지 13개월의 영수증 총액 |
| 여행 간 지출 비교 | 인식 완료·확인됨 | 통화·기간·검색으로 선택한 여행의 전체 영수증 총액 |
| 여행별 지출 구성의 분류 합계·막대·비율 | 인식 완료·확인됨 | 해당 여행의 품목 금액. 비율의 분모는 분류 합계 |
| 여행별 지출 구성의 영수증 총액 | 인식 완료·확인됨·검수 필요 | 여행 목록·상세와 같은 저장 총액 |
| 전체 CSV | 모든 저장 상태 | 모든 여행·영수증. 화면 필터와 별개이며, 원금액·상태·환산액·통계 포함 여부를 보존 |
| 여행 CSV | 해당 여행의 모든 저장 상태 | 해당 여행의 전체 영수증. 기간 필터로 결제 내역을 자르지 않음 |

인식 대기는 총지출과 통계에서 제외한다. 다른 결제 통화의 유효한 환율이 없으면 해당 금액도 제외한다. 환산 대기는 검수 상태와 별개이므로 같은 영수증이 두 상태의 장수에 함께 포함될 수 있다. 서로 다른 여행 기준 통화끼리는 합산하지 않는다.

사용자가 금액 불일치를 확인 완료 처리한 영수증도 통계에 포함된다. 따라서 모든 영수증이 확인됨이어도 영수증 총액과 품목 금액 합계가 항상 같지는 않다.

## 변경

- 통계 상단에 기본 접힘 상태의 ‘통계 집계 기준’ 안내를 한 곳에 둔다. 실제 상태색 태그와 함께 포함·제외 기준, 총액과 품목 금액의 차이, 환산·분류 비율의 기준을 설명한다. 고정 바로가기 행에는 포함하지 않는다.
- 각 여행의 분류 그래프 위에 ‘분류 합계’를 강조하고 ‘영수증 총액’을 작은 보조 금액으로 구분한다. 기존에 표시하던 총액은 보존한다. 두 합계는 같은 여행 기준 통화를 사용한다.
- 여행마다 반복되던 긴 제외·환율 설명은 제거하고, 필요한 검수 필요·인식 대기·환산 대기 장수만 상태 태그로 표시한다. 금액과 바로 연결되는 부분 집계·환산 대기 표시는 유지한다.
- 월별 그래프의 환산 대기 안내 장수는 실제 표시하는 13개월에 속한 인식 완료·확인됨 영수증으로 한정한다. 이전에는 기간 밖 과거·미래 영수증도 제외 장수에 섞일 수 있었다. 월별 금액 계산은 그대로다.
- 등록 안내의 ‘총지출’을 ‘여행 총지출’로 명확히 한다. 전체 CSV 안내에는 통화·기간·검색 조건과 독립적인 범위를 적는다.

## 오사카 검증

| 금액 | 결과 |
| --- | --- |
| 여행 목록·상세 / 영수증 총액 | 13,100엔 |
| 검수 필요 영수증 총액 | 3,800엔 |
| 분류 합계 | 9,300엔 |
| 여행 비교 / 2026년 4월 추이 | 9,300엔 |
| 분류 내역 | 식비 2,480엔 + 쇼핑 6,820엔. 검수 필요 품목은 제외 |

오사카의 기존 금액은 정상이며 그대로다. 화면에서 두 합계를 명명하고 안내를 정리했다. 검수 필요 영수증을 불일치 그대로 확인하면 비교·월별에는 영수증 총액 3,800엔이, 분류에는 품목 합계 7,600엔이 추가되는 것도 확인했다. 이후 내용 변경 시 다시 검수 필요로 판정되고 통계에서 제외되며, 품목을 바로잡으면 재포함된다.

## 개발 검증

- `npm test`: 57개 통과.
- `npm run build`: 타입 검사와 프로덕션 빌드 통과. 기존 OpenCV 브라우저 호환·번들 크기 안내는 유지된다.
- jsdom·가상 IndexedDB·한국 시간·고정 날짜(2026-11-23)를 사용한 집계/화면/CSV 회귀 시나리오 13건 통과. 실제 사용자 저장소나 외부 환율 서비스는 사용하지 않았다.
- 직전 커밋의 통계 렌더러와 모든 기존 영수증 총액·분류 막대·표시 비율·월별 금액·비교 금액/정렬/막대 폭을 대조했다. 금액 결과는 같다.
- 인식 완료·확인됨·검수 필요·인식 대기, 확인된 금액 불일치, 고정 환율·환율 없음·다른 날짜의 환율, 과거·미래·첫 달 경계, 한국 시간 자정, USD 소수 합계를 확인했다.
- 월별 환산 대기 안내는 모의 자료에서 전체 기간 6장이 아닌 표시 기간 3장을 가리킨다. 환율을 입력하면 관련 합계와 장수가 함께 복원된다.
- 전체/개별 CSV의 BOM 포함 바이트가 이전과 같고, 통계 포함 여부·원금액·대기 상태가 보존됨을 확인했다. 필터 조작과 화면 렌더링으로 원본 영수증·확인 상태·주소가 바뀌지 않았다.
- 통화·기간·검색과 빈 결과, 1080px 상한, 그래프 220px 높이·툴팁, 고정 바로가기·초점 이동을 확인했다. 실제 픽셀 배치와 가독성은 Mac 검수 대상이다.

## 사용자 검수

1. 통계의 ‘통계 집계 기준’을 펼쳐 상태별 기준을 확인한다. 긴 설명이 여행마다 반복되지 않아야 한다.
2. 오사카 샘플이 있다면 분류 합계 9,300엔 / 영수증 총액 13,100엔과 검수 필요 1장 태그를 확인한다. 샘플이 없으면 같은 금액으로 바꾸기 위해 새로 넣거나 기존 자료를 지울 필요는 없다.
3. 금액이 다른 확인됨 영수증이나 환산 대기가 있는 여행에서도 두 합계의 이름과 부분 집계 표시가 분명한지 확인한다.
4. 기간·검색·통화, 그래프 hover, 고정 바로가기와 CSV 동작을 확인한다.

## 사용자 후속: 직접 조회 기간·안내 한 줄

2026-11-23 사용자가 기존 변경을 긍정적으로 확인한 뒤 다음을 추가 지정했다. 이 후속까지 함께 검수한다.

- 공통 필터의 여행 기간 오른쪽에 조회 시작일·조회 종료일을 둔다. 여행 이름 입력 폭은 줄이고 날짜 범위를 같은 행에서 확인하게 한다. PC 창이 좁으면 날짜를 기간 옆에 유지하고 이름·조건 해제를 다음 행에 배치한다.
- 1년·3개월·1개월은 현지 오늘 기준 범위를 표시한다. 전체 기간은 현재 표시 통화에 속한 등록 여행의 가장 이른 시작일~가장 늦은 종료일을 표시한다. 이 네 항목에서는 날짜와 달력 버튼을 비활성화한다.
- ‘직접 설정’을 추가한다. 처음 고를 때 직전 프리셋의 날짜를 가져오며, 두 날짜를 직접 입력하거나 기존 `attachDateCalendar` 달력으로 고를 수 있다. 날짜 칸 클릭·달력 아이콘·키보드로 열 수 있다. 종료일 달력은 선택된 조회 종료일에서 연다.
- 달력은 기존 여행 수정 화면의 구현을 재사용한다. 조회 시작일/종료일 레이블과 입력 칸 클릭 열기 옵션을 추가했으며 기존 여행 종료일의 기본 동작은 유지한다. 프리셋으로 바꾸면 열린 달력도 닫고, 비활성 날짜 칸의 달력은 열리지 않게 한다. Popover 미지원 환경에서는 기존 브라우저 날짜 입력을 쓴다.
- 직접 날짜 범위와 여행 기간이 겹치는 여행을 비교·분류 양쪽에 함께 표시한다. 여행별 전체 금액·월별 추이·CSV 범위는 그대로다. 같은 시작·종료일은 유효하며 빈 날짜나 역전된 범위는 오류 안내와 함께 결과를 비운다.
- 통화 변경 시 직접 날짜·검색은 유지하고, 프리셋과 직접 설정을 오갈 때 기존 직접 날짜를 보존한다. 조건 해제는 직접 날짜도 지우고 전체 기간·빈 이름으로 돌아간다. 새 화면 진입의 기본값은 1년이다.
- 기존 날짜 범위 설명 문장을 제거한다. ‘기간·검색은 아래…’ 대신 ‘분류 합계는 검수 필요를 뺀 품목 금액, 영수증 총액은 검수 필요를 포함한 총액이므로 서로 다를 수 있습니다.’ 한 줄을 둔다.

후속 검증: `npm test` 57개·타입 검사/빌드 통과. 가상 DOM/IndexedDB에서 직접 범위·프리셋·비활성화·기존 달력 재사용·달력 선택·키보드·취소·유효성·통화/검색/해제·월말/윤년·금액/월별/CSV 불변을 다룬 11개 시나리오가 통과했다. 기존 여행 생성·수정 달력의 9개 통합 시나리오도 통과했다. 실제 날짜 칸의 가독성과 Popover 배치는 Mac에서 확인한다.

추가 화면 확인: 1년/3개월/1개월/전체 기간을 바꿔 비활성 날짜가 따라오는지, 직접 설정일 때만 두 달력이 열리는지, 날짜를 고르면 비교와 분류가 같이 바뀌는지 확인한다.
