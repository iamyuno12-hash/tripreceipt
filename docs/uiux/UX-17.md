## 문제와 변경

여행 목록·상세 화면은 기간에 연도를 표시하지 않아 서로 다른 연도에 걸친 `5월 12일 ~ 5월 8일`이 잘못된 순서처럼 보일 수 있었다. 기록이 여러 해 누적될 때 여행과 영수증의 연도도 구분하기 어려웠다.

`src/ui/format.ts`의 공통 표시 함수를 수정해 날짜에 항상 `YYYY년 M월 D일`을 표시한다. 기간은 같은 해여도 양 끝에 연도를 표시하며, 결제 일시는 연도와 기존 시·분을 함께 표시한다. 시간대가 있는 결제 시각은 기존처럼 브라우저 현지 시각으로 표시한다. 날짜만 있는 여행 기간은 시차로 날짜·연도가 이동하지 않도록 달력 날짜 그대로 표시한다.

| 표시 위치 | 변경 후 예 |
| --- | --- |
| 여행 목록·여행 상세의 기간 | `2024년 5월 12일 ~ 2025년 5월 8일` |
| 같은 해 여행의 기간 | `2024년 6월 10일 ~ 2024년 6월 12일` |
| 영수증 목록·영수증 상세의 결제 일시 | `2026년 11월 23일 00:30` |

## 전체 점검 범위

날짜 표시의 모든 호출 위치를 확인했다. 여행 목록·상세는 `dateRange`, 영수증 목록·상세는 `dateTime`을 사용해 공통 변경이 반영된다. 통계 월별 레이블은 이미 `YYYY.MM`, CSV 결제 일시는 이미 연도를 포함한 ISO 값이다. 날짜 입력 화면과 UX-01 달력도 연도를 표시하고 있다.

변경 파일은 `src/ui/format.ts`, 이 기록 문서, UX-01 사용자 확인 결과 기록이다. 저장 데이터·정렬·통계 계산·CSV 값은 수정하지 않는다.

## 완료 조건

- 연도를 넘기는 기간에서도 시작일과 종료일의 연도를 각각 식별한다.
- 같은 해의 기간과 영수증 목록·상세에서도 연도를 생략하지 않는다.
- 날짜만 있는 값은 시간대에 따라 전날·전년으로 바뀌지 않는다.
- 기존 시간 표시와 잘못된 값의 원문 반환 동작을 유지한다.
- 기존 테스트·타입 검사·빌드 통과 후 사용자가 실제 화면을 확인한다.

## 검증·커밋 기록

기존 테스트 39개와 타입 검사를 포함한 빌드가 통과했다. 표시 함수를 직접 실행해 다른 해·같은 해의 기간, 결제 시각의 연도 경계, 잘못된 값 반환을 확인했다. 한국 시간대와 미국 서부 시간대에서 날짜만 있는 값의 연도·월·일이 보존되고 결제 시각은 현지 시각으로 표시됨을 확인했다. `git diff --check` 통과. 새 자동 테스트 파일이나 프로젝트 의존성은 추가하지 않았다.

사용자 적용·실제 화면·최종 판정·커밋은 확인 후 갱신한다.

## 롤백

추가 수정 전에는 이 UX-17 패치에 `git apply --reverse --check` 후 `git apply --reverse`를 적용해 연도 표시 변경을 취소할 수 있다. 날짜 개선 묶음이 커밋된 뒤에는 해당 커밋을 `git revert`한다. 저장된 날짜는 표시 코드 롤백과 별개로 유지된다.
