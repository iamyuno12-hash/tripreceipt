## 문제와 목표 동작

시작일을 과거의 날짜로 선택해도 종료일 입력에 이미 들어 있는 날짜가 오늘이면, 기존 브라우저 달력은 오늘 부근에서 열려 같은 연월로 다시 이동해야 했다.

종료일 달력 버튼을 누르면 현재 입력된 시작일의 달을 먼저 보여 준다. 시작일 변경·달력 열기·월 이동·닫기만으로는 종료일 입력값이나 저장된 여행을 바꾸지 않는다. 날짜를 클릭해야 종료일 입력값이 바뀌고, 여행 저장 버튼을 눌러야 DB에 반영한다. 시작일이 비어 있으면 종료일, 둘 다 비어 있으면 오늘을 기준으로 연다.

## 구현 범위

| 파일 | 변경 |
| --- | --- |
| `src/ui/date-calendar.ts` | 표시 월과 선택 값을 분리하는 달력. 이전·다음 달, 날짜 선택, 닫기, 키보드 이동, 입력 변경 이벤트, 팝오버 닫힘 정리 |
| `src/ui/screens/trip-form.ts` | 새 여행·여행 수정의 종료일 입력에 달력 연결 |
| `src/style.css` | 달력 버튼·팝오버·날짜 표 스타일. 라이트·다크 테마 변수 재사용 |
| 이 문서 | 완료 조건·검증·사용자 확인·롤백 기록 |

기존 종료일 입력의 `type=date`, 이름, 직접 입력, FormData·저장 경로는 유지한다. 종료일이 시작일보다 빠를 때의 기존 오류 안내도 유지한다. Popover API가 없는 환경은 기존 브라우저 달력을 사용한다. 기본 지원·검수 대상은 팀 합의대로 PC Chrome이다.

브라우저의 `showPicker()`에는 표시할 월을 넘기는 매개변수가 없으므로, 값을 임시 변경하는 대신 앱 달력의 표시 월을 따로 관리한다. API 확인 자료: [HTMLInputElement.showPicker](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/showPicker), [HTMLElement.showPopover](https://developer.mozilla.org/en-US/docs/Web/API/HTMLElement/showPopover).

## 사용자 Mac에서 확인할 것

1. 새 여행에서 시작일을 2024-06-10으로 바꾸고 종료일 달력 버튼을 누른다. 종료일 입력값을 유지하면서 2024년 6월이 열리는지 확인한다.
2. 날짜를 고르지 않고 닫는다. 종료일이 달력을 열기 전 값 그대로인지 확인한다.
3. 다시 열어 2024-06-12를 선택하고 이름·지역을 입력해 저장한다. 다시 연 수정 화면에서 시작일·종료일이 각각 유지되는지 확인한다.
4. 실제 화면에서 달력이 입력창 근처에 표시되고, 날짜 클릭·월 이동·키보드·바깥 클릭 닫기가 정상인지 확인한다.
