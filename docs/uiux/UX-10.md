## 문제와 변경

통계에는 여러 기준 통화의 월별 추이·여행 비교·여행별 분류가 함께 나열되어 있다. 통계 상단의 ‘표시 통화’에서 원하는 집계 기준 통화 영역을 선택한다.

- 기본값은 ‘전체 통화’다. 등록된 여행의 실제 집계 기준 통화만 선택지로 표시한다. 여행 수가 많은 통화를 먼저 표시하고 동률은 통화 코드 순으로 정렬한다.
- 한 통화를 선택하면 그 통화를 기준으로 집계하는 여행의 월별 추이·비교·여행별 분류만 표시한다. 전체 통화로 돌아가면 기존 전체 영역이 복원된다.
- 필터 기준은 여행 통화다. 예를 들어 KRW 여행에 USD 영수증이 있어도 해당 여행은 KRW 필터에 나타나며 기존 고정 환율로 환산된 금액을 유지한다. USD 영수증이 있다는 이유만으로 USD 선택지를 만들지 않는다.
- 필터 변경은 화면에 보관된 데이터로 처리한다. 원본 영수증·상태·환율을 수정하거나 환율 API를 다시 호출하지 않는다. 기존 집계 함수와 통화별 그래프 값을 사용한다.
- 통화별 여행 수를 표시하고 선택 컨트롤의 포커스를 유지한다. 화면을 새로 열면 기본값인 전체 통화로 시작한다. 선택값을 저장소에 기록하지 않는다.
- 여행이 없으면 기존 빈 화면을 유지한다. 단일 통화·빈 여행·집계 가능한 영수증 없음·환산 대기도 해당 범위의 기존 안내를 유지한다.
- 전체 CSV는 필터와 관계없이 모든 여행을 내보낸다. 여행별 CSV는 해당 여행의 모든 영수증을 내보낸다. 필터 화면에 범위 설명을 표시한다.
- 여행 기준 통화가 다른 영역끼리 새로 합산하거나 환산하지 않는다. 이미 구현한 여행별 혼합 통화 환산은 유지한다.

## 변경 파일

- `src/ui/screens/stats.ts`: 표시 통화 선택·영역 갱신·여행별 통계 렌더 함수 분리.
- `src/style.css`: 기존 공통 선택 필드의 폭·간격.
- 이 문서와 `PROGRESS.md`: 완료 기준·검증·다음 작업.

## 개발 환경 검증

- 기존 자동 테스트 57개·타입 검사·프로덕션 빌드·공백 검사 통과.
- jsdom / fake-indexeddb 통화 필터 통합 시나리오 10개 통과. 2026-11-23 기준 날짜와 전용 예시 데이터로 검증했다.
- 제주 총액 221,000원, 오사카 총액 13,100엔 / 검수 필요 3,800엔을 제외한 분류·월별 합계 9,300엔, 기간 밖 오이도 12,700원 회귀값 확인.
- 전체→KRW→JPY→전체에서 같은 통화의 그래프·금액·막대 비율과 전체 복원 결과가 동일했다. 원본 DB와 네트워크 호출 수도 바뀌지 않았다.
- 필터 중에도 전체 CSV가 기존 전체 CSV와 UTF-8 BOM을 포함한 바이트 단위로 같음을 확인했다. 여행 CSV도 기존 여행 범위를 유지했다.
- KRW 여행의 USD 10·고정 환율 1400을 KRW 14,000으로 반영하고, 환산 대기·빈 통화 여행·단일 통화·여행 1개 사례를 확인했다.
- 2026-11-23 사용자 화면 검수 통과. 개발 환경의 모의 검증과 사용자 화면 검수를 구분해 기록한다.

## 사용자 검수

1. 통계 화면이 전체 통화로 시작하는지 확인한다.
2. KRW와 JPY 등 등록된 기준 통화를 번갈아 선택한다. 월별 추이·여행 비교·분류 영역이 함께 바뀌고, 표시되는 기존 금액이 같은지 확인한다.
3. 전체 통화로 돌아가 모든 영역이 복원되는지 확인한다. 외화 영수증이 있는 여행도 여행 기준 통화의 환산액을 유지하는지 확인한다.
4. 한 통화 선택 중 전체 CSV를 내려받아 다른 기준 통화의 여행도 포함되는지 확인한다.
