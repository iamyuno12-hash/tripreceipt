## UX-07 · 상세에서 삭제

변경 전에는 여행·영수증 자체를 지우려면 수정 화면에 들어가야 했다. 이제 상세에서 삭제에 접근하고, 수정 화면은 내용 편집·저장·취소에 집중한다. 영수증 수정의 품목 행 삭제는 편집 기능으로 유지한다.

- 여행 상세: 배경색이 있는 여행 요약 영역 안의 우측 상단에 여행 수정·삭제를 함께 배치한다. 여행 이름과 연결된 영수증·사진 삭제 범위를 확인창에 표시한다.
- 영수증 상세: 수정 옆에 영수증 삭제를 제공한다. 연결된 사진도 함께 삭제됨을 확인한다.
- 확인을 취소하면 데이터와 화면을 유지한다. 확정한 후 기존 저장소 삭제 함수를 사용한다.
- 영수증 삭제 후 해당 여행 상세로, 여행 삭제 후 여행 목록으로 복귀한다. 부모 여행이 없는 영수증의 삭제 후에는 목록으로 복귀한다.
- 처리 중 버튼을 비활성화해 중복 실행을 막는다. 오류가 나면 현재 화면에 이유를 표시하고 재시도할 수 있게 한다.
- 여행·영수증 수정 화면에서는 자체 삭제 영역을 제거한다. 입력·저장·취소 및 품목 행 편집은 유지한다.
- 저장소의 삭제 범위나 데이터 구조는 변경하지 않는다.

## UX-08 · 등록·검수 안내

여행 목록과 사진 등록 화면에 이용 순서를 짧게 표시한다. 이용 순서 제목은 주황색으로 강조하고 과정과 간격을 둔다. 세부 기준은 접힌 안내에서 더 작은 글씨로 확인할 수 있다. OCR 설명 첫 항목은 제거하고 인식 대기·검수 필요·환산 대기의 색 태그 오른쪽에 설명을 배치한다.

> 여행 선택 → 사진 또는 직접 입력 → 내용 확인·저장 → 통계

사진 등록의 ‘저장하고 내용 입력’은 사진·OCR 원문을 먼저 저장한다. 다음 수정 화면의 저장으로 상호·품목·금액을 확정해야 한다는 안내를 인식 결과 확인 단계에도 표시한다. 다른 사진을 선택하거나 처리 중일 때는 이 단계 안내를 지운다.

집계 설명은 최근 합의된 실제 동작을 따른다.

- 인식 대기: 품목·금액 저장 전이며 집계에서 제외.
- 검수 필요: 저장된 총액은 총지출에 포함. 분류·월별 추이·여행 비교에서는 제외.
- 확인됨·인식 완료: 해당 집계에 포함.
- 환산 대기: 환율이 없어 집계에서 제외하며 수정 화면에서 조회·직접 입력 가능.

사진 추출이 안 된 항목은 직접 입력할 수 있음을 알린다. OCR 엔진·파서·검수 판정·환산 로직을 추가로 변경하지 않는다.

## UX-09 · 오래된 설명 정리

이전 묶음에서 여행·영수증 화면의 P4/P5 미구현 문구를 제거했다. 이번에는 설정의 ‘CSV 내보내기가 추가되면’ 문구를 현재 통계 화면의 CSV 이동 안내로 바꾼다. CSV에 사진이 포함되지 않는다는 범위도 함께 설명한다. 수정된 화면 소스의 과거 단계 주석도 현재 동작에 맞춘다.

## 개발 환경 검증

- 기존 자동 테스트 57개, 타입 검사·프로덕션 빌드·공백 검사 통과.
- jsdom / fake-indexeddb 통합 시나리오 17개 통과. 실제 사용자의 데이터는 사용하지 않았다.
- 확인·취소, 관련 사진 삭제, 같은 여행의 다른 영수증·다른 여행 보존, 빈 여행·부모 여행 없는 영수증, 삭제 실패·재시도·중복 클릭 차단·완료 후 이동 확인.
- 수정 화면 자체 삭제 제거와 품목 행 삭제 유지, 이용 순서·접힌 상세 안내·샘플 안내 공존 확인.
- 고정 데이터로 총지출 1,120원 / 검수 필요를 제외한 분류 합계 620원을 확인해 안내와 계산이 일치함을 검증했다.
- 사진 등록의 안내 초기화, 실제 저장소 등록→수정 이동→폼 자동 채우기와 사진 펼침/OCR 접힘을 확인했다. 이 시나리오의 OCR 엔진과 사진 변환은 모의 구현이며 실제 인식 품질을 재검증한 것은 아니다.
- 사용자 기본 화면에 과거 P4/P5/P6 ‘추후 추가’ 안내가 남지 않았는지 확인했다.
- 실제 화면 배치·확인창·사진 가독성은 사용자 Mac에서 확인한다. 이전에 확인한 실행 환경 제한 때문에 Chromium 검증을 통과한 것으로 간주하지 않는다.

## 사용자 검수

1. 테스트용 여행과 영수증 상세에서 삭제 버튼을 확인한다. 먼저 취소해 기록이 남는지 확인한다.
2. 테스트용 영수증을 삭제하면 해당 여행으로 돌아오고, 다른 영수증은 유지되는지 확인한다. 테스트용 여행 삭제는 그 여행의 영수증도 함께 지우고 목록으로 돌아오는지 확인한다.
3. 여행·영수증 수정 화면에는 자체 삭제가 없고, 저장·취소와 품목 편집은 정상인지 확인한다.
4. 여행 목록·등록 화면의 이용 순서와 접힌 안내, 설정의 통계 CSV 안내를 확인한다.
5. 기존 핵심 입력·OCR·환산 결과가 유지되는지 확인한다.

## 사용자 디자인 보완 (2026-11-23)

- 이용 순서: 주황색 제목과 과정 텍스트 사이 20px 간격, 좁은 폭에서는 자연스럽게 줄바꿈.
- 하위 안내: 설명을 0.75rem로 줄이고 OCR 설명 첫 항목 제거. 세 상태의 태그·설명을 각각 왼쪽·오른쪽 열에 배치한다.
- 여행 요약: 일반 영수증 카드와 구분되는 회색 배경. 수정·삭제 버튼을 영역 내 우측 상단에 넣고 두 버튼 모두 무채색 배경으로 채운다.
- 여행 삭제 글자는 기존 위험 동작 색상인 빨간색을 유지한다. 무채색 요청은 버튼 배경에 적용한다.
- 설정 CSV 안내의 통계 화면 링크는 밑줄과 강조색으로 표시하고 안내 줄 전체를 0.7rem로 줄인다.
- 이용 순서 영역은 흰색 배경·별도 테두리로 상태 태그와 구분한다. 인식 대기 태그의 흰색 재정의는 제거해 앱의 실제 상태 색상을 따른다. 여행 요약은 푸른 회색 배경과 더 진한 2px 테두리로 일반 영수증보다 강조한다. 어두운 테마도 각각 대응한다.
- 좁은 폭에서는 버튼을 상자 안의 우측 상단 행에, 요약값을 그 아래에 배치한다. 어두운 테마의 주황색 제목·요약·버튼 배경도 정의한다.
- 삭제 확인·취소·오류·복귀와 집계 데이터는 유지한다. 디자인 구조·CSS 규칙 및 기존 흐름 모의 검증과 타입 검사·빌드를 확인한다. 실제 화면 배치는 사용자 검수 대기다.
