| 이미 있는 총액 | 저장된 총액·OCR에서 읽은 실제 총액은 합계와 달라도 유지. 재진입한 저장값을 자동 합계로 덮어쓰지 않음. 총액 수정이 품목을 역으로 변경하지 않음 |
| 잘못된 총액 저장 | 추가·수정 화면에서 총액 0·음수·비어 있는 상태는 저장 전 팝업으로 차단하고 총액 칸에 초점 복귀. 빈 칸을 유효한 품목 합계로 채울 수 있으면 채운 양수 금액으로 저장 |
| 확인 버튼 | 사용자의 마지막 요청대로 기존 표시 조건과 안내를 유지. 내용 미저장 또는 이미 확인됨이면 숨김, 내용 저장·실제 변경 후에는 저장된 내용과 판정에 따라 표시 |

부가세·환산 미리보기는 자동으로 채운 총액을 따라 갱신한다. 모드 선택을 위한 DB 필드를 추가하지 않는다. 사진 등록의 ‘저장하고 내용 입력’은 기존처럼 사진·OCR와 인식 대기 영수증을 먼저 보관한다. 이 단계의 0원 임시 레코드는 유지하며, 본문의 양수 총액 제한은 내용을 확정하는 영수증 추가·수정 폼에 적용한다.

## 확인 버튼 추가 조사

모의 OCR 자료로 실제 라우터의 사진 등록 → 사진·OCR 보관 → 내용 저장 전 이탈 → 수정 재진입 → 내용 저장을 연결했다. 정상적인 품목·양수 총액 저장 후 확인 버튼이 표시되었다. 이미 확인된 내용을 그대로 저장하면 숨김 상태를 유지했고, 총액을 변경해 저장하면 검수 필요와 확인 버튼이 다시 표시되었다.

따라서 정상 양수 내용 저장 후에도 버튼이 없다는 사용자 사례의 정확한 저장 데이터까지 재현한 것은 아니다. 사용자는 이어서 총액 0인 경우에 대해 확인 버튼 안내를 바꾸는 대신 저장 클릭에서 팝업으로 막도록 지정했다. 이 최종 요구를 반영했으며 확인 상태·판정 로직·버튼 표시 코드는 변경하지 않았다.

## 사용자 확인 순서

1. 통계에서 설명 오른쪽 ? hover, 표시 통화의 작은 안내·드롭다운 아래 현황·바로가기, 별표 미지정 일반 문구를 확인한다.
2. 여행 상세의 영수증 등록은 여행 선택이 잠겨 있어야 한다. 홈 최상단의 등록과 미지정 보관함에서 여는 등록에서는 여행을 고를 수 있어야 한다.
3. 새 영수증에서 수량 2·단가 5,500을 넣으면 총액 11,000이 채워진다. 총액만 12,000으로 바꿔도 품목은 11,000을 유지한다. 총액을 비우면 11,000이 다시 채워진다. 총액 0으로 저장하면 팝업이 뜨고 저장되지 않아야 한다.
4. 사진 검수는 짧게 나눠 확인한다: 사진 등록 → ‘저장하고 내용 입력’ → 수정 화면 아래 ‘저장’을 누르기 전에 뒤로 이동 → 다시 ‘수정’ → 품목·양수 총액 확인 후 ‘저장’ → 상세의 저장 내용과 확인 버튼 확인. 이미 확인된 영수증에서 내용을 그대로 저장한 경우에는 기존 확인됨을 유지한다.
